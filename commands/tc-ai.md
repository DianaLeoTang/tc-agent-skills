# /tc-ai

`$ARGUMENTS` 提供 specs 目录和代码仓库路径。根据当前项目推断明确的路径。每个编号功能目录应有 requirements.md、design.md 和 tasks.md。缺少规格时说明缺项，并指向 /tc-discuss 或 /tc-prd。

读取适用的项目规则和节点文件。优先使用项目覆盖，其次使用插件自带节点或全局安装。按 N1 初始化、N2 排序执行。每项任务依次完成 N3 实现、N4 评审、N5 更新进度、N6 风险验证和 N7 续跑记录。所有功能完成后执行 N8。

- 优先读取现有实现与验收标准，保留用户已有改动。只有依赖和文件归属明确隔离时才并行。
- 用真实入口验证改动，按风险补充检查。验证失败就定位和修复。若 N6 推翻已记录的结论，恢复对应任务为未完成并记录原因。
- 只有规格冲突会实质改变交付、缺少权限或外部依赖无法恢复时才暂停相关任务。独立任务继续推进。
- 在阶段完成、发现阻塞或改变方案时简要更新。交付时报告结果、验证证据及未验证项。
